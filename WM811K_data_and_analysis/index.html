Background

Wafer maps are spatial records of semiconductor test results. Each location on a map corresponds to a die on the wafer, and the pattern of passing and failing dies can reveal clues about process problems, equipment drift, contamination, edge effects, scratches, or other manufacturing issues.

Wu, Jang, and Chen describe wafer map failure pattern recognition as a useful tool for identifying failure causes and supporting large-scale semiconductor manufacturing analysis. This project builds on that background by treating wafer maps as image-like arrays and comparing a Random Forest baseline with CNN-based models for defect classification.

The class imbalance visible in this dataset is important: most labeled wafers belong to the none category, while several defect patterns have far fewer examples. This imbalance helps explain why accuracy alone can be misleading and why weighted F1 score, macro F1 score, confusion matrices, and per-class reports are included in the results.

Project Approach

Why Defect Detection Matters

  • Semiconductor wafers contain thousands of individual dies.
  • Defects lower manufacturing yield and can point to process or equipment issues.
  • Machine learning can help automate wafer-pattern recognition and reduce manual inspection time.

Dataset Preparation

  • The analysis uses labeled wafer maps from the WM811K dataset CSV export.
  • Each wafer is parsed, validated, and standardized to a uniform 26 x 26 map.
  • The current processed array shape is (74206, 26, 26).

Random Forest Baseline

  • Wafer maps are flattened into 1D feature vectors before training.
  • The current run fixes the baseline so Random Forest uses the same train/test split as the CNN models.
  • It remains strong overall, but recall is lower for several rare classes.

CNN Models

  • CNNs treat wafer maps as image-like inputs and learn spatial relationships between failing dies.
  • The current run normalizes inputs with X.astype("float32") / 2.0.
  • The improved CNN uses class weights, early stopping, and learning-rate reduction.

Current Test2 Notebook Plots

Processing Flow

The current notebook loads the WM811K CSV export, parses wafer-map strings, cleans label fields, removes unlabeled rows, validates maps, resizes maps to a uniform 26 by 26 grid, label-encodes defect categories, creates stratified train/test/validation splits, normalizes CNN inputs, trains Random Forest and CNN models, and evaluates predictions using accuracy, weighted F1, classification reports, confusion matrices, learning curves, and example wafer-map predictions.

Next Steps

Improve CNN Generalization

  • Keep early stopping so training stops before validation performance weakens.
  • Try smaller regularization changes before adding more model complexity.
  • Compare the old and improved CNN on the same split to avoid misleading curve differences.

Address Class Imbalance

  • Continue using class weighting so rare defect categories contribute more during training.
  • Use oversampling carefully, because the tested oversampling version made curves less stable.
  • Track macro F1 and per-class recall instead of relying only on total accuracy.

Expand Evaluation

  • Review mistakes between visually similar defect patterns.
  • Add normalized confusion matrices to compare class-level behavior more clearly.
  • Use similarity ranking ideas from the base research paper to support model interpretation.

Presentation Takeaway

  • Machine learning can automate wafer defect classification and reduce dependence on manual inspection.
  • The old CNN gives the best current test score, while the improved CNN has a more controlled training setup.
  • The largest challenge remains generalizing across imbalanced and visually similar defect classes.
